# Importing existing POs and carrier evidence

`scripts/import-procurement.mjs` bootstraps the procurement ledger from records
the owner already has. It is deliberately **dry-run by default**: it performs the
whole import in a temporary copy of the store and only writes when `--apply` is
passed.

The historical `procurement.txt` and `temu.txt` referenced in `PROCUREMENT.md`
are not present in this checkout. Do not recreate them from test fixtures or
memory: use the actual supplier confirmation, item list and carrier scans.

## Orders file

```json
{
  "orders": [
    {
      "created_at": "2026-09-27T09:00:00+01:00",
      "place": true,
      "request": {
        "external_id": "TEMU-270926-RAIS-WAFAE",
        "po_ref": "PO-TEMU-RAIS-WAFAE-270926-01",
        "supplier": "TEMU",
        "carrier": "AMANA",
        "origin": "owner_initiated",
        "prepaid_by": "swarm",
        "recipient_charge": false,
        "currency": "MAD",
        "recipient": { "name": "...", "city": "Rabat" },
        "items": [
          { "sku": "...", "qty": 1, "unit_price_mad": 1350, "expected_min_weight_kg": 0.6 }
        ]
      }
    }
  ]
}
```

`created_at` backdates **both** creation and placement, so contentieux aging is
truthful. `place: true` means the order was actually placed with the supplier;
omit it for a draft. A plain request object without `request` is accepted but is
left as a draft.

`--orders` may also be a JSON array or a single request object.

## Evidence

```json
{
  "po_ref": "PO-TEMU-RAIS-WAFAE-270926-01",
  "carrier": "AMANA",
  "tracking": "AMANA-OWNER-TEMU-270926",
  "scans": [
    { "status": "PICKUP", "at": "2026-09-27T14:05:00+01:00", "location": "Casablanca" },
    { "status": "HUB", "at": "2026-09-27T21:40:00+01:00", "location": "Casablanca tri" },
    {
      "status": "DELIVER",
      "at": "2026-09-28T10:22:00+01:00",
      "destination_city": "Agdal, Rabat",
      "weight_kg": 2.55,
      "pod_reference": "POD:AMANA-sha256:<real digest>",
      "signed_by": "..."
    }
  ]
}
```

`--evidence` accepts one JSON file or a directory of `*.json` files. Only the
AMANA adapter exists; other carriers are reported as unsupported rather than
guessed. Evidence is matched by `po_ref`, then by the PO's recorded tracking
number. Unmatched evidence is reported and never attached to another order.

## Commands

```bash
npm run procurement:import -- --orders orders.json --evidence scans/ --dry-run
npm run procurement:import -- --orders orders.json --evidence scans/ --apply
npm run procurement:import -- --orders orders.json --evidence scans/ --apply --json
```

`--data-dir` overrides `data/procurement`; `--min-days` controls the contentieux
summary threshold.

## Safety rules

- No scan, weight, city, POD or receipt is generated by the importer. A delivery
  is recorded only when the supplied evidence passes the existing carrier/timeline
  rules. Missing or invalid POD leaves the PO `on_hold` with hold codes.
- A delivered PO is still not verified without a goods receipt and invoice; it
  appears in contentieux with the missing evidence listed.
- Orders are idempotent by `external_id`; re-running does not create duplicates.
- Evidence is only applied while a PO is `shipped`. Delivered, held or unmatched
  evidence is reported, not rewritten.
- The importer never contacts a supplier or carrier and never moves money.

After `--apply`, the next audit/tick picks up the POs and JARVIS shows the
resulting cases.
